# Storage Architecture

PostgreSQL stores evidence metadata, hashes, relationships and integrity data.
Large evidence files use Laravel filesystem abstraction.

## Evidence disk
The dedicated `evidence` disk is private and rooted at:
`storage/app/evidence`

It is not exposed through `public/storage`.
Storage write failures throw exceptions so evidence persistence errors are not silently ignored.

## Adapters
- local private filesystem for development/testing
- S3-compatible object storage for future staging/production

## Rules
- do not store large binary evidence blobs directly in PostgreSQL
- never trust client-provided filenames
- object keys are generated by application code
- metadata and integrity hashes remain in PostgreSQL
- production buckets must be private by default
- public/signed access requires an explicit use-case and authorization check

A future ADR is required before changing the authoritative storage model.
